# 訪談腳本

多數人不擅長講自己的作品。不是謙虛,是**當事人看不到自己的特別之處** —— 對他來說那只是「當時的工作」。訪談的作用是把他習以為常的東西問出來。

---

## 通則

**一次問一題。** 一次丟五個問題,會得到五個敷衍的答案。

**追問到具體為止。** 「優化了效能」不是答案,「從 240×180 提升到 4K」才是。

**聽到「我們」就停下來。** 問:「這一段裡,哪一部分是你自己做的?」

**聽到「還好啦」「這沒什麼」要特別注意。** 使用者最常低估的,往往是最有價值的部分 —— 因為對他來說太理所當然了。

**不要幫他把話說完。** 你補的形容詞會變成他不敢認的宣稱。

---

## 定位訪談

目標是找到主線。**沒有主線的作品集只是清單。**

```
1. 你希望誰看到這頁?
   → 追問到具體職稱或情境。不接受「大家」「有興趣的人」。

2. 他們看完之後,你希望他們認為你是什麼樣的人?

3. 他們看完之後,你希望他們做什麼?

4. 如果只能留一句話,你希望是哪一句?

5. 你的經歷裡,有沒有一條線把看似無關的東西串起來?
```

### 第 5 題答不出來時

這很常見,而且**正是使用者最需要你的地方**。不要把問題丟回去。

做法:回到候選池,找出重複出現的動詞與模式,提出 2–3 個具體的主線選項讓他挑。

> 例:「你的東西有個共同點 —— 每一段都是接手一個還沒被定義清楚的問題,
> 然後把它變成可以測量、可以驗證的系統。要不要用『我把模糊的想法,
> 整理成能實際運作的系統』當主線?」

給選項,不要給開放式問題。使用者會知道哪個像自己,但不一定生得出來。

---

## 風格訪談

```
6. 給我 1–2 個你覺得「我想要這種感覺」的網站,以及你喜歡它哪裡。
   → 「喜歡哪裡」比網站本身重要。

7. 讀起來要像:專業嚴謹 / 親近好懂 / 有觀點有主張?

8. 訪客願意花多久讀?
   → 決定長文案例還是精簡卡片。

9. 有沒有什麼是你絕對不想呈現的樣子?
   → 常常最有用。排除比選擇更能定義風格。
```

---

## 逐件深度訪談

每個要做成完整案例的項目都要走完:

```
1. 這是什麼作品或事件?
2. 當時要解決什麼問題?
3. 你本人負責哪些部分?          ← 追問到「你」
4. 哪個決策是你做的?            ← 決策比執行更能展現能力
5. 最後產生什麼成果?
6. 有什麼證據?                  ← 沒有這題就只能寫敘述,不能寫宣稱
7. 希望誰看到?
8. 哪些內容不能公開?
```

### 挖出好故事的追問

最有說服力的內容通常不在「我做了什麼」,而在「哪裡卡住、怎麼解開」:

- 這個專案裡最難的一天是哪一天?
- 有沒有什麼問題,原因跟你一開始想的完全不同?
- 有沒有哪次是所有人都認為是 A 的問題,結果是 B?
- 你做過最不甘願但事後證明正確的決定是什麼?
- 如果重來一次,你會怎麼做?

這些問題會挖出**可轉移的判斷力** —— 那是讀者真正會記住的東西,也是履歷寫不出來的東西。

### 挖出量化成果的追問

使用者常常有數字但不覺得值得講:

- 這件事影響到多少人 / 多少台 / 多少次?
- 前後差多少?
- 省下多少時間或成本?
- 有沒有什麼是「如果沒做會怎樣」?

## 精選訪談

```
10. 這些裡面,哪三件最能代表現在的你?
11. 有沒有哪一件你不想再被關聯?
12. 有沒有什麼你覺得很小、但其實花了你很多心力?
```

取捨不下時,用這個判準排序:

**擁有度 × 證據強度 × 與主線的相關性**

擁有度低或拿不出證據的,不要當主打。放進次要卡片即可。

---

## 收尾確認

寫完之後,拿成果給本人確認這三件事(不是確認你的工作過程):

1. 事實對不對
2. 角色描述準不準
3. 有沒有不能公開的內容

確認完,填入案例的 `confirmed` 日期。
